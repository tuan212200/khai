# GitHub Copilot Review Instructions - React Native Project

## General Code Quality
- Name clear (variables, functions, components)
- Code logic matches requirements
- No unused code or console logs
- Suggestions are reviewed and validated
- Code is modular and maintainable
- No hardcoded secrets or credentials
- Validation and error handling present
- name component start by  A

## React Native Specific
- [ ] Components use TypeScript with proper interfaces for props
- [ ] All interactive elements have `testID` for E2E testing
- [ ] Uses `ThemedText` and `ThemedView` from existing components
- [ ] Styles use `StyleSheet.create()` for performance
- [ ] Cross-platform compatibility (iOS/Android/Web) considered
- [ ] Proper keyboard handling with `KeyboardAvoidingView` for forms
- [ ] Loading states implemented for async operations

## TypeScript Standards
- [ ] Interfaces defined for all props and complex data structures
- [ ] No usage of `any` types (use proper typing instead)
- [ ] Event handlers and state properly typed
- [ ] Import statements use proper TypeScript paths

## Testing Requirements
- [ ] Components have unit tests with React Testing Library
- [ ] TestIDs follow naming convention: `component-element-purpose`
- [ ] E2E tests use proper Detox syntax with descriptive selectors
- [ ] External dependencies are properly mocked in tests
- [ ] Test files located in correct directories (`/components/*.test.tsx`, `/e2e/*.test.js`)

## Accessibility & UX
- [ ] Accessibility props added (`accessibilityLabel`, `accessibilityHint`)
- [ ] Screen reader friendly component structure
- [ ] Form validation with clear error messages
- [ ] Proper focus management for navigation

## Performance & Best Practices
- [ ] Uses React hooks appropriately (`useState`, `useEffect`, `useThemeColor`)
- [ ] Implements proper error handling with try/catch blocks
- [ ] Theme-aware styling with `useThemeColor` hook
- [ ] Components follow established file structure patterns
- [ ] Optimized rendering (avoid unnecessary re-renders)

## Security & Data
- [ ] Input validation on all user inputs
- [ ] Sensitive data not logged or exposed
- [ ] API calls include proper error handling
- [ ] State management follows React best practices

## Code Organization
- [ ] File placement follows project structure:
  - Components: `/components/ComponentName.tsx`
  - Unit tests: `/components/ComponentName.test.tsx`
  - E2E tests: `/e2e/component-name.test.js`
  - Screens: `/app/(tabs)/screen-name.tsx`
- [ ] Consistent code formatting and style
- [ ] Proper separation of concerns
